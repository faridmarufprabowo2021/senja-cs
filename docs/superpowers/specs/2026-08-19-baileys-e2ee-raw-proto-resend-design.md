# Design Specification: Baileys Raw Proto Store & E2EE Auto-Resend Enhancement

**Date:** 2026-08-19  
**Status:** Approved by User  
**Target Subsystem:** `apps/api` (WhatsApp Baileys Driver, Prisma Schema, Bot & Inbox Sending Pipeline)

---

## 1. Overview & Objective

In WhatsApp Multi-Device E2E Encryption (Signal Protocol), recipient clients display **"Waiting for this message. This may take a while"** (*Menunggu pesan ini...*) when the recipient's phone cannot decrypt an incoming message frame and initiates a peer resend request (`PEER_DATA_OPERATION_REQUEST_RESPONSE_MESSAGE`).

When WhatsApp's client requests a resend via Baileys' `getMessage(key)` callback, returning simplified text or plain JSON structures fails WhatsApp's internal cryptographic hash check. To solve this permanently for the Baileys engine:

1. Capture the exact `proto.IMessage` structure generated by Baileys on every outbound message (`sendText` / `sendMedia`).
2. Store raw proto structures in a fast in-memory LRU cache (`rawMessageCache`) and persist them to PostgreSQL (`prisma.message.rawProto`).
3. Return the exact, complete `proto.IMessage` from `getMessage(key)` when resend receipts arrive.
4. Ensure automatic pre-key upload (`uploadPreKeys(50)`) on session initialization.

|            │                                                                  |
|            ▼                                                                  |

|            │                                                                  |
|            ├──► Check Memory LRU Cache ──(Found?) ──► Return Raw proto        |

|     (creds.update & connection.update)                                        |
|            │                                                                  |

## 3. Component Details

### 3.1 Schema Update (`packages/shared` or `apps/api/prisma/schema.prisma`)
Add `rawProto String? @db.Text` to the `Message` model:
```prisma
model Message {
  id             String    @id @default(cuid())
  // ...
  waMessageId    String?   @index
  rawProto       String?   @db.Text
  // ...
}
```

### 3.2 Baileys Driver (`apps/api/src/wa/drivers/baileys.driver.ts`)
- **LRU Cache**: `private rawMessageCache = new Map<string, any>()` (capped at 1,000 recent outbound items).
- **Outbound Storage**:
  - In `sendText(jid, text)`:
    - Save `sent.message` to `rawMessageCache.set(sent.key.id, sent.message)`.
    - Return `{ ...sent, rawProto: JSON.stringify(sent.message) }`.
  - In `sendMedia(jid, opts)`:
    - Save `sent.message` to `rawMessageCache.set(sent.key.id, sent.message)`.
    - Return `{ ...sent, rawProto: JSON.stringify(sent.message) }`.
- **`getMessage(key)` Callback**:
  - Check `this.rawMessageCache.get(key.id)`. If present, return it immediately.
  - If missing in memory, query `prisma.message.findFirst({ where: { waMessageId: key.id } })`.
  - If `dbMsg?.rawProto` exists, parse JSON and return the parsed `proto.IMessage`.
  - If still missing, return `undefined`.
- **PreKey Upload**:
  - On `connection.update` when `connection === "open"`:
    - Call `this.socket.uploadPreKeys(50)` asynchronously to ensure WhatsApp servers hold fresh PreKeys.

### 3.3 Message Persistence Pipeline (`apps/api/src/wa/manager.ts`, `apps/api/src/bot/reply.ts`, `apps/api/src/routes/inbox.ts`)
- When creating a `Message` in Prisma DB:
  ```typescript
  await prisma.message.create({
    data: {
      // ...
      waMessageId: sent?.key?.id ?? undefined,
      rawProto: sent?.rawProto ?? (sent?.message ? JSON.stringify(sent.message) : undefined),
    }
  });
  ```
